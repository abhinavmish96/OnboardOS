# OnboardOS: the AI business launch orchestrator

Built for the YC Hackathon with **Terse**, **Agent Relay**, **OpenAI ChatKit**, and **Supabase**.

Three autonomous agents — Finance, Document, and Compliance — coordinate the accounting setup for a new subscription business. A human reviewer approves every document before launch. When something's wrong, the agents correct each other through real Agent Relay messages, regenerate the document, and send it back for approval.

## The stack

| Technology | Role |
|---|---|
| [Terse](https://github.com/TerseAI/durable-actors) (durable actors) | Each onboarding is a single actor with `@Persisted` state in SQLite. Kill the process, restart — nothing lost. |
| [Agent Relay](https://github.com/AgentWorkforce/relay) | Real agent-to-agent DMs between Finance, Document, and Compliance agents. Every message is durable and inspectable. |
| [OpenAI ChatKit](https://openai.com/chatkit) + Agents SDK | Onboardy, the in-dashboard chat assistant. Answers questions about launch status by calling the same API the dashboard uses. |
| [Supabase](https://supabase.com) | Postgres stores onboarding snapshots, an append-only event log, version-tied approvals, and Onboardy's chat history. |

## Run the demo

### Prerequisites

- **Node 22+** — `nvm install 22 && nvm use 22`
- **Bun 1.4.2+** — `curl -fsSL https://bun.sh/install | bash`
- **Agent Relay** — `npm install -g agent-relay`

### First-time setup

```bash
# Agent Relay
agent-relay init --tools none --port 8787
agent-relay agent register finance_agent
agent-relay agent register document_agent
agent-relay agent register compliance_agent

# Install dependencies
cd web && npm install
cd ../backend && npm install
cd actors && bun install
cd ../..

# Supabase (optional — falls back to local files without it)
cp .env.supabase.example .env.supabase   # fill in the DB password
cd web && node scripts/db-migrate.mjs
```

### Start (4 terminals)

```bash
# Terminal 1: Agent Relay
agent-relay node up

# Terminal 2: Terse actor runtime
cd backend && ./start-actors.sh

# Terminal 3: Backend API
cd backend && npx tsx src/index.ts

# Terminal 4: Dashboard
cd web && BACKEND_URL=http://localhost:4000 npm run dev -- -p 8000
```

Optional extras:
```bash
# Landing page
cd landing && npm run dev -- -p 8001

# Onboardy chat assistant
cd agent && echo "OPENAI_API_KEY=sk-..." > .env && ./run.sh
```

## The demo flow

1. **Start** SpookyStream onboarding — three agents auto-generate accounting documents in ~6 seconds.
2. **Watch** the activity feed: Finance Agent hands off to Document Agent via Agent Relay, Compliance reviews both documents.
3. **Reject** Ledger Mapping v1: *"Refund transactions must reverse deferred revenue, not recognize new revenue."*
4. **See** the Finance Agent → Document Agent correction thread — real Agent Relay messages, not simulated.
5. **Ledger Mapping v2** appears with changed cells highlighted against v1.
6. **Approve** both documents → status becomes **Launch Ready**.
7. **Kill the backend, restart it, refresh** — nothing is lost. That's Terse.
8. **Ask Onboardy** *"Where are we?"* — it reads the live workflow state through the same API.
9. **Advance clock 25h** → overdue escalation event fires.

**Invariant:** launch is ready only when every document's latest decision *for its current version* is an approval. A revision makes old approvals stale. A review for the wrong version returns **409 `stale_version`**.

## API

All shapes defined in `shared/contract.ts`. The dashboard and Onboardy both use these endpoints.

| Endpoint | What |
|---|---|
| `POST /api/onboardings` | Start a new onboarding (defaults to SpookyStream) |
| `GET /api/onboardings/:id` | Full authoritative snapshot |
| `GET /api/onboardings/:id/events?after=<seq>` | Append-only event stream |
| `POST /api/onboardings/:id/review` | Approve or reject a document version (idempotent) |
| `POST /api/onboardings/:id/clock` | Advance the demo clock for SLA testing |

## Database (Supabase)

| Table | What |
|---|---|
| `onboardings` | Snapshot + runtime state (pending steps, SLA clocks) |
| `events` | Append-only history (updates and deletes refused by trigger) |
| `approvals` | One row per decision, tied to a document version |
| `chat_threads`, `chat_items` | Onboardy conversations |
